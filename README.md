# Creating Users with PowerShell

**Hands-on Microsoft Azure / Windows Server lab** · Active Directory Domain Services · PowerShell · User provisioning · Windows 11 · Remote Desktop

## Project overview

Automated **Active Directory user provisioning** in an Azure-hosted Windows Server domain, verified the accounts in **Active Directory Users and Computers (ADUC)**, configured Remote Desktop access for standard domain users, and signed in to a Windows 11 workstation using a newly generated account.

Built on the [Active Directory Deployment](https://github.com/starlight0658/Active-Directory-Deployment) lab. This project documents **user creation with PowerShell and non-administrator domain access (Part 2)**, rather than repeating the earlier domain-controller setup.

**Skills demonstrated:** PowerShell ISE · `New-ADUser` · Active Directory bulk provisioning · organizational units · user and group administration · Remote Desktop permissions · domain authentication · Windows client troubleshooting.

## Lab environment

| Component | Configuration |
| --- | --- |
| Cloud platform | Microsoft Azure |
| Domain controller | `DC-1` — Windows Server 2025, AD DS / DNS |
| Client workstation | `Client-1` — Windows 11 Pro, domain joined |
| Active Directory domain | `mydomain.com` (isolated lab domain) |
| Employee OU | `_EMPLOYEES` |
| Administrator account | `jane_admin` (lab domain administrator) |
| Example standard domain account | `bame.siv` (generated by the script) |
| Scripting environment | Windows PowerShell ISE, run as administrator |
| Remote workstation access | Windows App / RDP from macOS |

## Implemented and verified

1. **Configured standard-user RDP access:** Enabled Remote Desktop on `Client-1` and added `MYDOMAIN\Domain Users` to the allowed Remote Desktop Users list.
2. **Prepared PowerShell provisioning:** Opened PowerShell ISE on `DC-1` with administrative privileges; loaded a script that generates sample names and provisions accounts with `New-ADUser` in `_EMPLOYEES`.
3. **Executed bulk account creation:** Ran the script and observed continuous account-creation output. The script was configured with a target of **10,000** accounts; screenshots verify user creation and script completion, **not** an independently audited total of exactly 10,000 successful accounts.
4. **Verified directory objects:** Confirmed newly created user objects in ADUC under `_EMPLOYEES` and inspected a sample account's properties and default `Domain Users` membership.
5. **Tested non-administrator login:** Authenticated to `Client-1` as the generated account `bame.siv` and verified its domain identity, interactive Windows session, and newly created `C:\Users\bame.siv` profile.

## Lessons and security considerations

- **Account count accuracy:** The screenshot of the sample script initializes `$count = 1` and loops while `$count -lt 10000`. As written, it attempts **9,999** iterations, not 10,000. A production run should use an explicit account-count assertion and check for errors/duplicates.
- **Credential hygiene:** The sample script uses a shared, hard-coded **lab-only password** and enables password-never-expires accounts. These are demonstration settings, **not** suitable for a production directory. Use approved secret handling, unique credentials and organizational password policies instead; rotate/delete disposable credentials after the lab.
- **RDP least privilege:** Granting the entire `Domain Users` group access to one test machine helped demonstrate normal-user authentication. For a real enterprise environment, restrict RDP to a dedicated authorized group and manage settings through Group Policy, with strong network controls and auditing.
- **Provisioning safety:** Perform bulk operations in a dedicated test OU, validate input and resulting account counts, and avoid accidentally creating many real identities or consuming production resources.
- **Resource management:** The Azure VMs were retained for subsequent AD practice. Stop/deallocate them when not needed to limit charges.

Demonstrated the progression from **scripted directory provisioning** to **verification in ADUC** and a **successful standard-domain-user Windows login** — an end-to-end workflow relevant to IT support, Windows administration, and entry-level identity and access management.
